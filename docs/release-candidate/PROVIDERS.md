# External provider review

Reviewed November 9, 2026, for Floody's controlled, noncommercial school demonstration. Limits refer to the documented tiers and hosts identified below. A successful HTTP response does not establish permission for public or commercial deployment.

| Provider | Documented terms | Floody status and follow-up |
| --- | --- | --- |
| Geoapify geocoding | API key required. Free tier lists 3,000 credits/day and up to 5 requests/s, shared by keys in one project. Autocomplete, forward and reverse each cost one credit per request. Free-tier use requires a Geoapify follow link and applicable data-source credits. Caching is permitted subject to attribution and terms. [Pricing](https://www.geoapify.com/pricing/) · [Credit costs](https://www.geoapify.com/pricing-details/) · [Geocoding attribution and retention](https://www.geoapify.com/geocoding-api/) | Web and native link Geoapify, OpenStreetMap and OpenAddresses near address entry. Recife validation returned both underlying datasets. All three operations share a five-starts-per-second limit per runtime and back off on 429. Web retains the most recent successful query for 30 seconds per mounted field. No persistent autocomplete cache, background autocomplete, or automatic retry. Validate project-wide traffic and any additional source credits before broadening coverage. |
| OSRM demo routing | No key for current demo calls. The OSRM wiki records historical terms for `router.project-osrm.org`, including low usage, identification and OSRM/ODbL attribution. It points to FOSSGIS for its current demo, which publishes one request/s and a map correction link requirement. That numeric limit is documented for the FOSSGIS host. No current numeric or caching rule was verified for Floody's exact legacy host. [OSRM wiki](https://github.com/Project-OSRM/osrm-backend/wiki/Api-usage-policy) · [FOSSGIS usage](https://routing.openstreetmap.de/about.html) | User-initiated calls only. Both platforms link OSRM, OpenStreetMap copyright and map corrections for either layer. Exact host terms and actual request identity need review before wider use. Keep demo requests infrequent and avoid bulk calls. The demo host offers no SLA. |
| Open-Meteo | Free endpoint is for noncommercial use, including educational use. Limits below 10,000/day, 5,000/hour, 600/minute and 300,000/month listed on the plan table. No free-tier key. Data is CC BY 4.0. [Terms](https://open-meteo.com/en/terms) · [API and model interval](https://open-meteo.com/en/docs) | Dashboard and route label the model interval, validity time and freshness, and link source and license. Weather refresh runs once per minute only on the foreground dashboard, with no persistent cache. Route weather is requested separately and never gates the route. Reassess aggregate volume before opening access to many clients. |
| OpenStreetMap raster tiles | No key or guaranteed SLA. Normal interactive viewing is allowed with visible attribution, identifiable clients/valid browser Referer, HTTPS, and HTTP cache compliance. Honor response headers or retain tiles at least seven days if the cache cannot read headers. Bulk downloads and offline prefetch are prohibited. No published general numeric cap. [OSMF tile policy](https://operations.osmfoundation.org/policies/tiles/) | Default streets use the official tile URL and display OSM credit. Native WebView adds `Floody/1.0`. No offline downloads. Actual native request headers and cache behavior need device verification. Use normal interactive viewing only for the demo. |
| CARTO | Current basemap documentation requires a key for CARTO-hosted raster and vector tiles and visible CARTO and OpenStreetMap credits. It lists 5 million noncommercial tile requests/month and 1 million commercial requests/month at the free tier, counted across keys on the account. [CARTO basemaps](https://docs.carto.com/faqs/carto-basemaps) | Recognized CARTO hosts receive both credits on web. CARTO is absent from checked-in default URLs. Before enabling it, confirm the exact key, terms and cache policy for the chosen tile URL. |
| Esri World Imagery | Esri requires proper credit and reserves the right to classify noncommercial use. Public responses do not establish an unrestricted third-party license. No general numeric quota or offline caching right was established for this legacy endpoint. [Service terms](https://www.esri.com/en-us/legal/terms/web-site-service) · [World Imagery service metadata](https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer?f=pjson) | The old satellite attribution omitted contributors. The corrected layer uses the service metadata credits and reports a switch to streets on tile failure. Rights and any extent-specific credits remain unverified. Use streets for the controlled demonstration. |
| INMET via RadarMeteorológico | INMET issues the alerts; RadarMeteorológico republishes them. Public feed allows commercial and noncommercial reasonable use without a key and requests linked credit. Alerts are cached ten minutes. No numeric cap or SLA is stated. [Feed conditions](https://radarmeteorologico.com.br/api-publica) · [Official INMET source](https://avisos.inmet.gov.br/) | The app links both sources, shares collection requests, respects the ten-minute cadence and identifies cached data during outages. No location coordinates are sent to the alert endpoint. Suitable as a supplementary feed in the demo. |
| Parallelum FIPE v1 | The operator documents 500 unauthenticated calls per 24 hours, or 1,000 with a free token. No specific cache/redistribution permission was found on the v1 reference. [Operator's v1 documentation](https://deividfortuna.github.io/fipe/) | Uses unauthenticated make/model queries and labels the catalog FIPE. Web makes load on entry to the garage and are retained in the current app session. Native catalog requests are tied to the picker. User-entered garage data remains local. Confirm attribution, cache and reuse conditions before expanding public use. |

Geoapify public keys are visible in the Expo bundles and network requests. Keep local configuration in ignored `Floody/.env.local`. Use separate demo keys with appropriate restrictions, monitor the shared project usage, and rotate a key if exposed beyond its intended audience. For web, verify an allowed origin or referrer rule. CORS controls access to the response, while origin, referrer or IP restrictions govern API access. Native has no reliable browser referrer. Key restrictions were not audited in the provider console. [Geoapify key restrictions](https://myprojects.geoapify.com/help/api-keys/)

Address text goes to Geoapify during web typing after 600 ms and three letters or digits, or when a lookup is submitted. GPS coordinates are sent to reverse geocoding only after a user requests the report location. Do not use private home addresses or real incident details in shared demonstration captures.
